Proposed Work Flow

System Architecture & Pipeline

How sensor data flows from physical hardware inputs through processing to real-time alerts and cloud storage.

1

Sensors (Input)

Collects raw telemetry data from Gas, Smoke, Flame, Temperature, and Air Quality sensors continuously.

  • • Gas Sensor (MQ-2)
  • • Temp & Humidity (DHT11)
  • • Smoke & AQI (MQ-135)
  • • Flame IR Sensor
2

Control Unit

The NodeMCU / ESP32 microcontroller processes analog/digital signals using C/C++ firmware.

  • • Microcontroller Processing
  • • Signal Conditioning
  • • Wi-Fi Data Transmission
3

Analyze & Logic

Python backend & logic evaluates incoming sensor streams against safety threshold algorithms.

  • • Threshold Detection
  • • Python Data Analysis
  • • Trend Evaluation
4

Alert & Action

Triggers immediate local hardware alerts (Buzzer & Red LED) and updates cloud dashboard.

  • • High-Decibel Alarm
  • • Visual LED Alert
  • • Web Dashboard Warning

Hardware & Software Specifications

Industrial-grade components integrated for high reliability and swift response.

Hardware Platform

Physical sensors, controllers & alert actuators

MQ-2 Gas Sensor Detects LPG, Methane, Smoke, Flammable gases.
DHT11 Temp & Humidity Digital ambient temperature and humidity sensor.
MQ-135 Air Quality Monitors hazardous airborne gases & air purity.
Buzzer & LED Module High-decibel audible alarm and warning light.
ESP32 / NodeMCU Controller 32-bit Wi-Fi enabled microcontroller for fast signal processing.

Software Architecture

Embedded firmware, analytics and dashboard

C / C++ Firmware Microcontroller code for fast sensor reading logic.
Python Data Analysis Processing trends and evaluating hazard probabilities.
Web Dashboard UI Responsive real-time monitoring interface.
Cloud Database Remote telemetry storage for historical audit reports.
Wi-Fi Protocol (MQTT/HTTP) Low-latency data transmission from edge nodes to cloud.
